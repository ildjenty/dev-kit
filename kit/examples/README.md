Detection examples verify whether an aspect produces the expected judgments with its assigned runner. Paths starting with `schemas/` or `checks/` below are relative to the installed kit copy root.

`<aspect_id>/spec.json` is JSON with `aspect` and `cases`. Each case has `kind` (`violation`, `conforming`, or `allowed`), `file` relative to the specification file, and `expected` (`FAIL`, `PASS`, or `PASS`, respectively). Each example is Markdown with `## Request` and `## Target`, using fictional inputs, artifacts, and observation records. Keep expected judgments and case kinds in the specification; give the judge the example body, frozen norms, and the supplied output schema. Return observations with `schemas/detection-result.json`; each observation contains a judgment following `schemas/judgment.json`. Run tests with the runner assigned by the plan. For violation examples, also check that findings cite the applicable blocking condition. For conforming and allowed examples, check that differences in judgment or exemptions are not ignored to block them. Include the example body and expected judgment in the content hash; follow `checks/README.md` for pass identity and storage and `schemas/detection-result.json` for result observations. Listing an expected judgment is not a pass record; record a pass only after obtaining the actual judgment and its grounds.
