Stores violation, conforming, and allowed examples for detection tests.
Aspect files belong in kit/checks/; detection test specifications and comparison logic belong in internal/check.
For placement, see `docs/architecture/modules.md#kit`; for detection test handling, see `docs/architecture/modules.md#check`.

`<aspect_id>/spec.json` is JSON with `aspect` and `cases`, following the format in `docs/architecture/examples.md`. Each case has `kind` (`violation`, `conforming`, or `allowed`), `file` relative to the specification file, and `expected` (`FAIL`, `PASS`, or `PASS`, respectively). Each example is Markdown with `## Request` and `## Target`, using fictional inputs, artifacts, and observation records. Keep expected judgments and case kinds in the specification; give the judge the example body, frozen norms, and output schema. Run tests with the runner assigned by the plan. For violation examples, also check that findings cite the applicable blocking condition. For conforming and allowed examples, check that differences in judgment or exemptions are not ignored to block them. Include the example body and expected judgment in the content hash; follow DetectionTest in `docs/architecture/data.md` for pass identity and storage. Listing an expected judgment is not a pass record; record a pass only after obtaining the actual judgment and its grounds.
