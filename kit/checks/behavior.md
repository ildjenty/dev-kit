# behavior

- 確認事項: 共通: 起動、操作、コンソールエラー、証拠の取得、後片付けを確認する。 データの変更: 保存した内容と読み出した結果が仕様どおりか。 外部との通信の変更: 送受信の内容と失敗時の扱いが仕様どおりか。 画面を変える場合: 画面の規則（`docs/rules.md#画面`）に従う。描画結果と操作の確認は `principles/ui.md` の原則9（`principles/ui.md#9-描画結果と操作を確認する`）に従い、長い名前、0件、大量のデータ、多言語など、問題が起きやすいデータも使う。
- blocking: 保存した内容や読み出した結果、送受信の内容、通信の失敗時の扱いが仕様と異なる。画面を変える場合は、同原則9の blocking 条件に該当する、または画面の規則に違反する場合も blocking とする。未確認の扱いは同原則9に従う。
- 報告しない事項: この観点の確認事項に含まれない事項。失敗のシナリオを示せない指摘。
- 出力形式: 依頼で渡された Judgment の JSON Schema と `docs/architecture/data.md` の Judgment・Finding に従う。必要な判断基準や必須の確認を得られない場合は `NOT ASSESSED` とし、確認済み・未確認の範囲と方法・環境を残す。失敗のシナリオを示せない指摘は返さず、重大度は付けない。指摘は全件残し、blocking でない指摘は参考情報とし修正を求めない。適用除外の主張と根拠を照合し、外れる要求に限って違反としない。
