# router — 次のアクションの決定

router は、少数の分類と規則をまとめた表である。

## 人への確認

- **分類・ルーティング先**: 作業を停止して確認する / 暫定判断で進めてレビューで確認する / 人による確認は不要
- **適用場面**: [check](check.md) の `needs-decision`、[brief](brief.md) に沿った作業中の判断、計画に設ける人によるレビューゲート。
- **承認**: 未回答や「いいえ」を同意として扱わず、承認が必要な範囲は承認されるまで実行しない。

## check の結果

- **分類・ルーティング先**: 修正する / 人に確認する / 前の[ステージ](../stages.md)に戻る / 完了する
- **適用場面**: 各ステージの check が終わった後。
- **完了条件**: 計画の必須 check の集合と現在の対象の版に対する結果を照合し、未実施・古い版・`NOT ASSESSED`・`FAIL` の必須 check があれば「完了する」に進めない。

## 教訓の反映先

- **分類・ルーティング先**: hook・lint・型 → 原則 → skill の手順 → kit に戻す。規則を守らせる強制力は、文章 < skill の手順 < テスト < lint・型 < hook の順に強くする。
- **適用場面**: 指摘や失敗が発生したとき。同じ手順の繰り返しやコピーに気づいたとき。
- **移行の記録**: 規則の強制手段の移行先はこの分類で決め、決定 ID と出力を ledger の「規則と強制手段」の移行記録に結び付ける。

## ロールとエンジン

- **分類・ルーティング先**: ロール（作成・批評・調査・執筆）→ モデルと effort、またはモデル名を指定した Codex
- **適用場面**: 計画で各ステージの担当を決めるとき。

## 振り返りの判定

- **分類・ルーティング先**: 採用 / 却下 / 保留
- **適用場面**: 振り返りで出た案を分類するとき。

「作業を停止して確認する」に分類する事項は [`principles/working.md`](../../principles/working.md) の原則10に従う。

**計画に人によるレビューゲートを設けるときも、この分類に基づいて理由を書く。** 元に戻せない変更だけが対象ではない。

判断の基準と可逆な変更の扱いは `principles/working.md` の原則10、check の失敗が続いたときの前提の見直しは [`principles/harness.md`](../../principles/harness.md) の原則3、違反が再発したときの強制手段の見直しは `principles/harness.md` の原則4に従う。
