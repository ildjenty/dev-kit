# view — 人向けの表示

view は [ledger](ledger.md) と構造の資産から人向けの静的 HTML を生成する。報告全体をモデルに書かせず、モデルが書くのは短い「理由」欄だけにする。

## 入力と出力

- **入力**: ledger と、構造ステージを使う場合の `.devkit/structure.json` の解析済みの値を受け取る。構造の git の履歴は cmd/devkit が workspace で取得して渡す([view の契約](../architecture/modules.md#view))。
- **出力**: `devkit view` で静的 HTML を生成する。表示の責務と依存は [view の契約](../architecture/modules.md#view)に従う。

## 冒頭の固定形式

view の冒頭は、人が戻る間隔と進んだ作業の量にかかわらず、同じ固定形式で次の内容を短く示す。

- **目的と対象**: 目的と、対象の課題。
- **現在の到達点**: 課題ごとの現在の到達点。
- **実行状態**: 待ちと失効を含む[ステージの実行](../architecture/data.md#ステージの実行-stagerun)の状態、停止理由、次に動く主体を示す。作業中には最後の観測時刻を添える([view の契約](../architecture/modules.md#view))。
- **人の次の行動**: 次にすべき行動を1つ示す。なければ「対応不要」とし、全課題が終わっていれば「次の課題を選ぶ」とする。
- **記録の網羅性**: `submit` が成果物を記録した範囲を示す。網羅性の入力は [view の契約](../architecture/modules.md#view)に従う。

## 主表示

主表示は次の3群とし、同じ対象は1か所にだけ表示する。

- **要対応**: 今、作業を止めているもの、暫定判断で進んでいるが人の回答が要るもの、再検討の条件を付けた保留の順に分ける。
- **現在の到達点と有効な変更**: 成果ごとの正味の差分として、できるようになったこと、外から見える振る舞い・契約の変化、構造の変化を示す。現在有効な暫定判断と、それを撤回したときの現在の影響（依存する成果・決定、無効になる確認、ロールバックの成立条件）も示す。完了条件ごとに、対象のバージョン、方法、確認した範囲、未確認の範囲を示す確認範囲の地図を設ける。構造の変化は、影響箇所から示し、全体図へ展開する。
- **経緯**: 置換された判断、古くなった確認、戻した変更のうち残る効果（外部への書き込みなど）、履歴を示す。

「新着」「未確認」「承認済み」は群にせず、各項目の属性として付ける。「有効な変更」は[成果物](../architecture/data.md#成果物-artifact-record)の記録から生成する。

## 判断対象ごとの表示

固定した層を上から順に読ませるのではなく、要対応の各項目は、判断対象ごとに次の内容を1か所に束ねる。

- 問い。選択肢、推奨案と理由を、[form の人への確認事項](form.md#人への確認事項)から引き継ぐ。
- 関連する暫定判断。
- 影響する変更。
- 確認状況の要点。主体、判定（`PASS` / `FAIL` / `NOT ASSESSED`）、対象のバージョンと規範の識別の一致、承認状態を別々に示す。有効性の条件は [Judgment](../architecture/data.md#check-の結果-judgment)に従う。
- 前回の人の判断と、それが成立した条件、今回変わった条件。
- 未回答のとき止まる範囲と、独立して進められる範囲。
- 根拠へのリンク。決定と [check](check.md) の記録をたどれるようにする。

問いの範囲の表示と実際の停止の関係は、[状態遷移と受理条件](../architecture/data.md#状態遷移と受理条件)に従う。

## 閲覧と状態変更

読了の目安は、一律の層ではなく、目的ごとの必読集合で示す。「この回答に必要な確認」と「状況把握のために残っている確認」を分け、それぞれ対象のバージョンと残件数を示す。件数で打ち切らず、残りの項目と省略した詳細への入口を残す。

閲覧と確認済みの集合は、[状態変更](../architecture/data.md#決定と証拠-decision--evidence)から導く。HTML からは状態を変更せず、チャット経由の `answer` で記録する([人の回答と再開](../architecture/flow.md#人の回答と再開))。

人による確認の要否は[人への確認対象](../architecture/guarantees.md#人への確認対象)に従う。構造の変化と暫定判断は、check が通っていても人が読む。

## 構造図

構造図は、[構造の記録](../architecture/data.md#構造の記録-structure)から Mermaid のテキストとして生成する([view の構造図の生成](../architecture/modules.md#view))。図の描き方は [`principles/writing.md`](../../principles/writing.md) の原則8に従い、入力に関係の種類がなければ依存関係の図までにとどめる。

## 試験項目

- 固定の ledger と構造による冒頭の固定形式、3群の主表示、判断対象ごとの表示、完了条件 ID ごとの確認範囲の地図。
- 待ち・失効・最後の観測時刻、判定の有効性、状態変更から導く確認済みの集合。
- 成果物による網羅性と、問いの範囲の表示および停止との関係。
- 静的 HTML の描画結果。

試験の範囲と描画結果の確認は[契約の試験項目](../architecture/contract-changes.md#試験項目)に従う。
