# ledger — 状態の外部保存

ledger は、人向けの表示を生成できる構造化データとして保持する。モデルが生成した文章を、そのまま状態として扱わない。**セッションをまたいで参照する記録の正本は ledger とする。** Issue や PR は成果の公開先であり、そこに転記する前でも ledger の内容は有効である。

すべての記録は、記録 ID と、課題・計画の版・実行 ID・対象の版への参照を持つ。[view](view.md) は、この参照によって記録を結び付ける。理由の文章を機械に解釈させて、記録間の関係を補わない。

## checkpoint

- **記録方法**: 上書き。25行以内。
- **内容**: 現在の作業状況、確認済み事項、不具合のある箇所と未確認事項、次のアクション、作業中の変更禁止事項、使用するコマンド。SessionStart で読み込む。コンテキスト圧縮（compaction）後も同様とする。

## 計画

- **記録方法**: 版を残す。
- **内容**: [ループ計画](../loop-plan.md)。各版の承認者も記録する。

## 決定

- **記録方法**: 追記のみ。
- **内容**: 時刻、[ステージ](../stages.md)、決定内容、理由、却下した案、根拠、元に戻せるか、ロールバック手段、決定者（人・エージェント）、暫定判断か委任の範囲内の確定判断か、適用条件（判断が成立する条件）、現在有効か、置換した決定・置換された決定への参照、この決定に依存する成果・決定・[check](check.md)、状態（未読・承認・却下・保留）。

## check の結果

- **記録方法**: 追記のみ。
- **内容**: 時刻、ステージ、[観点](../checks.md)、**対象の版**、確認した完了条件の ID、確認した範囲と確認していない範囲、方法と環境、判定、指摘（blocking ではないものも含む）、実行者、解決した指摘への参照。対象の版が現在と異なる結果は「古い」として扱う。後の check が同じ条件を確認していれば、古い結果は対応事項から外し、経緯に残す。

## ステージの実行

- **記録方法**: 追記のみ。
- **内容**: 実行 ID、ステージ、開始・完了の記録、実行状態（実行中・回答待ち・中断・異常終了・不明）、状態を観測した時刻、停止理由、次に動く主体（エージェント・人）。外部への書き込みがある場合は、冪等キーと結果も記録する。再開時に [runtime](runtime.md) が照合する。

## 成果物

- **記録方法**: 追記のみ。
- **内容**: 成果物の ID と版、変更前後、対応する完了条件の ID、変更の種類（できるようになったこと・外から見える振る舞いや契約の変化・構造の変化）、変更を生んだ決定への参照。view の「有効な変更」は、この記録から生成する。

## 記録範囲の照合

- **記録方法**: 追記のみ。
- **内容**: 実行の区切りごとに、変更された成果物・実行記録と ledger の記録を照合した結果。照合した範囲、未照合の範囲、対象の版を記録する。view の冒頭で、記録の網羅性を示すために使う。

## 構造

- **記録方法**: 版を残す。
- **内容**: モジュール、責務、配置、依存の向き。必要に応じて、関係の種類と、その関係が生じるトリガー（書く・無効化する・読む）も持つ。各版の承認者を記録し、この記録から図を生成する。

## 規則と強制手段

- **記録方法**: 更新する。
- **内容**: 規則、それを守らせる手段（hook・lint・テスト・文章）、出典、見直す時期。

## カーソル

- **記録方法**: 上書き。
- **内容**: 表示に含めた記録の集合とその版、その中で実際に確認した記録・承認した記録。時刻は、経緯の絞り込みにだけ使う。

記録は逐次書き込む。改行、タブ、数式として解釈される文字は除く。列の構成、バージョン管理方法、関係の種類など、記録の形式は `parts/ledger` の契約で定める。参照・有効性・置換・依存の列の詳細も、この契約で定める。
