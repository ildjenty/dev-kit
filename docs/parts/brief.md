# brief — 作業依頼のフォーマット

- **ゴール**: 何を、誰のために行うのか。
- **完了判定**: コマンドの実行結果、または観察できる結果によって、`pass` と `fail` を判定できる条件。
- **提示する根拠**: 完了条件を満たしたことを、どのように示すか。
- **既知の情報**: 症状、再現手順、ログ。本文を渡すのではなく、参照先のパスを渡す。
- **スコープ**: 変更してよいものと、変更してはいけないもの。
- **停止条件**: ラウンド数の上限、進展がなかった回数、人に判断を求める必要が生じた場合。
- **返却内容**: 人の判断が必要な事項、未確認の事項、自分で決めた事項、参照しなかった入力。

個々の作業を依頼する brief には、具体的な進め方や原因の仮説を含めない。ループ計画は brief の一種だが例外で、ステージの順序、担当、check、レビューゲート、戻る規則を持つ。受け取った側の着手手順は [`principles/working.md`](../../principles/working.md) の原則1に従う。

brief は、[ステージ](../stages.md)間の引き継ぎ、人からループへの依頼、ループからサブエージェントへの依頼、skill のスコープの宣言に使う。ステージ間の引き継ぎでは、ステージ N の出力がステージ N+1 の brief になる。
