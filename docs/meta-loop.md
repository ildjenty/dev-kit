# メタループ

## メタループ

メタループは、harness 自体を改善するためのループである。別の仕組みを設けるのではなく、同じループの作業対象を harness にする。

- **入口**: 指摘、失敗、振り返りで出た案を、[router](parts/router.md) の「教訓の反映先」で振り分ける。共通する内容は kit に戻す。
- **振り返り**: 判断の誤り、ツールと仕組み、代替手段という3つの視点で会話の記録を読む。案は「採用」「却下」「保留」に分類する。作業の途中では harness を修正しない。
- **改善の手がかり**: [check](parts/check.md) の結果の記録（blocking ではない指摘も含む）と、人が後から発見した見逃しを手がかりにする。**人は check の結果から意図的に一部を選んで読み直し、自分の判断と check の判定を照合する。** 偶然の発見には頼らない。同種の問題が繰り返される場合は、[観点](checks.md)・原則・lint として取り込む候補にする。
- **検査**: 「harness」「skill の試験」「前提の批評」の観点で確認する。観点「harness」では [`principles/harness.md`](../principles/harness.md) を読む。
- **整理・削減**: 原則の整理の候補と期間は [`principles/README.md`](../principles/README.md) の「更新方法」に従う。使われなかった観点・skill も同じ基準で候補にする。削除するかどうかは、未使用の期間ではなく、その仕組みが必要になる代表的なケースで比較して決める。検出感度の試験と整理・削減は、別の実験として扱う。

harness の変更は [`principles/working.md`](../principles/working.md) の原則10の停止事項に含まれる。手がかりの自動集計は、何を測るべきかが分かるまで実装しない。

## 設計の2〜3割に生じる問題

設計の2〜3割には、配置の不自然さや冗長さが生じる。生成時に気付けることは期待せず、[ステージ](stages.md)2の check で検出する。観点「構造」では、これらを blocking とする。

- **配置の誤り：配置ガイドがない。**: リポジトリに配置ガイドを用意し、ステージ2の check が参照する。
- **冗長さ：制約ごとに仕組みを足したり、既存コードを変更せずにレイヤーを追加したりする。**: 観点「構造」で、より単純な構造を1つ作って比較する。[`principles/design.md`](../principles/design.md) の原則「追加する前に削除する」「たどるレイヤーと覚える状態を減らす」と、各原則の違反・兆候を使う。
- **前提への固着：Issue に書かれた手段に設計が縛られる。**: ステージ0では目的だけを固定し、手段はステージ2で決める。観点「構造」で、その手段自体を疑う。
- **1回だけの生成：一度の生成で設計を済ませる。**: ステージ2の check を、別のコンテキスト・別系統のエンジンで実行する。

採用しなかった設計は、上の4分類で [ledger](parts/ledger.md) に記録する。どの分類が多いかを見て、観点を改善する。
