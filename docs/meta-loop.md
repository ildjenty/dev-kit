# メタループの運用

## メタループ

メタループは、ループの仕組み(部品、組み立て、計画)を評価して改善するためのループである。毎回の作業の最後に作業者が `retrospective` を担当し、リポジトリの規範と機械の検査を育てる。既定の `default`・`fix`・`docs` はいずれも振り返りで終わる。

振り返りの入力は[依頼の入力](architecture/data.md#依頼の入力)、再発防止の反映先と規範の変更の確認は[教訓の反映先](architecture/guarantees.md#教訓の反映先)に従う。人への確認が必要だったか、任せるべきだったかは[線引きの更新](architecture/guarantees.md#線引きの更新)で扱う。履歴と必須 check は[ループの決まり](architecture/data.md#ループの決まり)に従う。

規範全体が目的を果たしているか、どの原則がどの観点・パターンで使われるか、使われない仕組みや負担に見合わない仕組みがないかを確かめる。扱う対象はその作業の問題・見逃し・規範の不足や負担であり、全体の棚卸しは必要が見えた場合に行う。削除するかどうかは、未使用の期間ではなく、その仕組みが必要になる代表的なケースで比較して決める。

完了後に見つかった見逃しは、新しい `fix` の課題として扱い、その振り返りで反映先を決める。人は check の結果から一部を選んで読み直し、自分の判断と判定を照合できる。

`status` と view は記録から、ステージの実体ごとのラウンド数(振り返りでは定義ごとの集計も含む)、人に止められた回数と理由、担当の切り替え、依頼文の大きさを作業ごとに集計する。集計のために新しい記録は足さない。作業全体の上限 `[limits] max_total_rounds` を設定した場合の確認と累計は[計画のバージョン](architecture/data.md#計画のバージョン)に従う。

## 生成した設計の典型的な問題

生成した設計には、配置の不自然さや冗長さが生じることがある。[ステージ候補](stages.md)の「0 目的」「2 アーキテクチャ」「4 詳細設計」では、次の問題が手がかりになる。検査と blocking の基準は観点「[構造](checks.md#構造)」に従う。

- **配置の誤り**: 成果物を本来の配置先と異なる場所に置く。配置ガイドの欠如が原因・兆候となる。ガイドの配置と取り込みは[リポジトリ側の構成](repository.md#リポジトリ側の構成)に従う。
- **冗長さ**(制約ごとに仕組みを足す、既存コードを変更せずにレイヤーを追加する): より単純な構造との比較は観点「[構造](checks.md#構造)」に従う。判断には [`assets/principles/designing.md`](../assets/principles/designing.md) の原則5と [`assets/principles/structure.md`](../assets/principles/structure.md) の原則7の違反・兆候を使う。
- **前提への固着**(Issue に書かれた手段に設計が縛られる): 目的と手段を決める範囲はステージ「[0 目的](stages.md#0-目的)」「[2 アーキテクチャ](stages.md#2-アーキテクチャ)」「[4 詳細設計](stages.md#4-詳細設計)」に従い、観点「[構造](checks.md#構造)」で前提を照合する。
- **1回だけの生成**(一度の生成で設計を済ませる): check の [`FAIL`](architecture/data.md#check-の結果-judgment)(不合格の判定)に対する修正ラウンドは[作業結果の判定](architecture/flow.md#作業結果の判定)と [router](architecture/modules.md#router)(次の行動を分類する部品)の[判断](architecture/flow.md#router-の判断)に従い、設計を作り直す。
- **既存の流儀の無視**(同じ種類の処理があるのに、既存の書き方と異なる実装を追加する): 調査と成果物はステージ「[調査](stages.md#調査)」「[2 アーキテクチャ](stages.md#2-アーキテクチャ)」「[4 詳細設計](stages.md#4-詳細設計)」、照合は観点「[構造](checks.md#構造)」「[差分](checks.md#差分)」に従う。

却下した設計案の記録は[決定と証拠](architecture/data.md#決定と証拠-decision--evidence)に従い、用途別の判定基準を改善する手がかりにする。
