Plan templates are JSON files named `<name>.json`, such as default, feature, fix, and docs. `devkit init` copies defaults to `.devkit/plans/`, where repository owners maintain templates selected by `devkit start --plan <name>`.

Templates follow `schemas/plan-template.json`; task-specific plans follow `schemas/plan.json`, and planner responses follow `schemas/planner-result.json`. These paths are relative to the installed kit copy root. Templates define stages, assignees, checks and runners, gates with reasons, limits, and transitions. Gate reasons are free text; use the classification name when one in `router/README.md` applies.

Build the smallest plan for what changes. Remove unrelated stages, select needed optional stages, give completion conditions IDs, and assign each check a target and completion condition IDs. Preserve task-specific irreversible decisions in the plan; shared decisions and their enforcement and grounds belong in `.devkit/rules.md`. Stages changing UI, data, or external communication need behavior checks. Required judge-run aspects follow `checks/README.md` for detection tests.

Adding stages outside the template candidates, removing gates, changing transitions, or removing required checks are deviations requiring human approval; mark applicable findings `needs-decision` using `schemas/finding.json`. Omitting initial stages and changing the start stage that way is not a deviation. Declared external operations require a human approval gate even without deviations; declarations identify kind, target, input hash, definition hash, and executable content hash. See `skills/devkit/SKILL.md` for external operations and human-requested plan changes. Propose replanning when completion conditions or premises need changing; do not silently treat a proposal as the active plan.
