Detection examples verify whether an aspect produces the expected judgments with its assigned runner. Examples are installed alongside repository-owned aspects as `checks/<aspect_id>/spec.json` and the example files it names. See `checks/README.md` for detection test requirements.

`checks/<aspect_id>/spec.json` is JSON with `aspect` and `cases`. Each case has `kind` (`violation`, `conforming`, or `allowed`), `file` relative to the specification file, and `expected` (`FAIL`, `PASS`, or `PASS`, respectively). Each example is Markdown with `## Request` and `## Target`, using fictional inputs, artifacts, and observation records. Give the judge only the example body as test input, together with frozen norms and the supplied output schema. Do not give the judge the specification, case kind, file name, or expected judgment; devkit compares the returned judgment with the expectation. Return observations with `schemas/detection-result.json`; each observation contains a judgment following `schemas/judgment.json`. Run tests with the runner assigned by the plan. Devkit compares verdicts only; a matching verdict does not establish that a violation failed for the intended reason. Retain findings and grounds for review. For conforming and allowed examples, check that differences in judgment or exemptions are not ignored to block them. Include the example body and expected judgment in the content hash; follow `checks/README.md` for pass identity and storage and `schemas/detection-result.json` for result observations. Listing an expected judgment is not a pass record; record a pass only after obtaining the actual judgment and its grounds.
