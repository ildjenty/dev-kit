# Increments

Review the release division, completion condition coverage, and demonstration path.

## What to check

- The first increment connects the user interface through to data and includes startup and testing, with explicit conditions for verifying the skeleton.
- Each increment has completion condition IDs, a scope, a verification method, and size grounds showing it fits within one implement instance's limits.
- The ordered increments cover all agreed completion conditions and can be demonstrated through the user's entry point. One increment is enough for a small task.

## Blocking

A completion condition is uncovered, the skeleton has no verifiable condition, or an increment cannot be verified or fit within its implement limits.
