# Brief request templates

These repository-owned Go `text/template` sources define work, judgment, and planning requests under `templates/brief/`.

- `templates/brief/work.md.tmpl`: The current stage, task and plan, verification, repository facts, fixed norms, previous outputs and findings, and command or pre-commit output. Change boundaries come from scope outputs and rules.md. Retrospective requests also include all judgments and findings, FAIL and NOT ASSESSED history, round counts, human responses, lessons about missed issues, and the norm inventory. Return the progress block using `schemas/progress.json` and `devkit submit <file>`.
- `templates/brief/judgment.md.tmpl`: The judgment content, instruction ID, repository requirements, relevant structure records, rules, and fixed norms. Detection tests supply example bodies without case kinds or expected judgments; devkit compares the returned actual judgments with expectations. Return a JSON-only final message using the supplied schema (`schemas/judgment.json`, or `schemas/detection-result.json` for detection tests).
- `templates/brief/planner.md.tmpl`: The original user request, the task supplied to start, loop template, stage definitions, repository facts, fixed norms, available checks, and any current or remaining plan, human instructions, and previous findings. An unobserved original request is explicitly marked as absent. Unresolved requirements belong in `open_questions`, without guesses. Return a JSON-only final message using `schemas/planner-result.json` with a plan following `schemas/plan.json`.

The binary supplies the output schema as text. Inline inputs contain the applicable stage definition, the aspects being judged and the principles they reference, rules.md, requirements.md, and relevant structure.json records. Other norms are listed by logical name and fixed snapshot path; read them when needed from that expansion, not from the working tree. The snapshot is fixed at round start, or when an instruction outside a round is issued.

Template inputs use `Norms` for selected inline norm documents (`Path` and `Content`) and `NormPaths` for the remaining norms (`Path` for the logical name and `SnapshotPath` for the fixed expansion path). `Repository.Requirements.Content` supplies requirements.md in all three briefs. `Repository.LayoutGuides` contains only relevant structure records; `Repository.Rules` supplies rules.md. Judgment content supplies the applicable stage and aspect. `OriginalRequest` preserves the original user text for planning, or is empty if none was observed. `RetrospectiveContext` supplies the retrospective inputs for work at that stage.

Read the full generated request and its references, and retain its `instruction_id` in the result. Follow `stages/README.md` for work submission and completion, `checks/README.md` for judgments, and `plans/README.md` for planning.
