# test

- Checks: Follow `principles/testing.md`. For each completion condition assigned to this check, identify concrete tests and check whether they run through a command registered in `devkit.toml`. Inspect the tests and command execution path, not just a passing command or the author's report. Verify contracts through the user-visible entry point; for a CLI, check arguments, standard output, standard error where specified, and exit codes. Check that expected values come from the agreed contract and that tests observe behavior rather than reproduce implementation logic or assert internal details outside the contract. Apply the referenced principle's requirements and exemptions for test selection, failure detection, existing behavior, and changed contracts.
- blocking: A completion condition assigned to this check has no concrete test executed through a registered command, the relevant user-visible contract is untested, or a blocking condition in `principles/testing.md` applies.
- Do not report: Items outside this aspect's checks. Findings without a failure scenario. Requests for additional tests that would duplicate the same guarantee under the same premises without detecting a different failure.
- Output format: Follow the Judgment JSON Schema supplied in the request (`schemas/judgment.json`) and `schemas/finding.json`, with the judgment rules in `checks/README.md`. Return `NOT ASSESSED` when necessary criteria or required verification are unavailable, and record the verified and unverified scope, method, and environment. Do not return findings without a failure scenario, and do not assign severity. Retain all findings; treat nonblocking findings as reference information without requiring fixes. Compare exemption claims with their grounds, and waive only the requirements covered by the exemption.
